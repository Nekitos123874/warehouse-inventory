\# Архитектура проекта Warehouse Inventory



\## 1. Описание системы

Система представляет собой REST API для учёта складских товаров. Она позволяет менеджерам склада добавлять новые товары, обновлять их количество и получать актуальные остатки.



\## 2. Выбор компонентов (C4 Level 2)

В архитектуру включены следующие обязательные и дополнительные компоненты:



\*   \*\*API Gateway:\*\* Выступает единой точкой входа. Обеспечивает безопасность (проверка токенов) и перенаправляет трафик к API.

\*   \*\*Inventory API Service (Java 17):\*\* Основной сервис, содержащий бизнес-логику обработки товаров.

\*   \*\*PostgreSQL Database:\*\* Основное хранилище данных. Используется для надежного хранения таблицы товаров.

\*   \*\*Redis Cache (Дополнительный компонент):\*\* Выбран для кэширования. 

&#x20;   \*   \*Обоснование выбора:\* В системах складского учета запросы на чтение (просмотр остатков) происходят в десятки раз чаще, чем на запись (приход/расход). Кэширование в Redis позволяет отдавать список товаров за миллисекунды, не нагружая PostgreSQL.



\## 3. Взаимодействие

1\. Клиент отправляет HTTP-запрос на API Gateway.

2\. Gateway проверяет права и передает запрос в API Service.

3\. Если запрос на чтение (GET), сервис сначала проверяет Redis Cache. 

&#x20;  \* Если данные есть — отдает их.

&#x20;  \* Если нет — идет в PostgreSQL, берет данные, отдает клиенту и сохраняет в Redis.

4\. Если запрос на изменение (POST/PUT/DELETE), сервис обновляет данные в PostgreSQL и \*\*сбрасывает\*\* устаревший кэш в Redis.
